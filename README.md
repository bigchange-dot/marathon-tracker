# 🏃 마라톤 트래커 — 2026-11-15 풀코스

풀코스 마라톤 완주를 위한 개인 훈련 트래커 PWA.
서버·DB 없이 정적 파일로만 동작하고, 기록은 브라우저(localStorage)에 저장된다.

## 사용법

- 폰 브라우저로 접속 → 메뉴에서 **"홈 화면에 추가"** 하면 앱처럼 사용
- **오늘**: D-day, 이번 주 진행률, 다음 훈련과 기록 입력
- **캘린더**: 14주 전체 스케줄, 계획 vs 실적, 놓친 훈련 표시
- **통계**: 주간 거리(계획 vs 실적)·페이스·통증 차트 + 기록 테이블
- **가이드**: 대회 전략, 페이스 가이드, 통증 신호등, 보강 운동, **JSON 백업/복원**

> 기록은 브라우저에만 저장되므로 **주 1회 JSON 내보내기**로 백업할 것.
> (2주 이상 백업이 없으면 앱이 리마인드 배너를 띄운다)

## 훈련 플랜

### 1차 검토 (Gemini 초안 → 수정)

| 항목 | 초안 | 수정 | 이유 |
|---|---|---|---|
| 피크 롱런 | 32km | **28km + 시간 상한 3:30** | 런워크 페이스로 32km는 4시간 이상 — 부상 위험 > 훈련 효과 |
| 롱런 증가 | 25→28→32 | 단계적 증가 + 시간 상한 | 신스프린트 이력자에게 +3~4km 점프는 재발 구간 |
| 롱런 시간대 | 오후 권장 | **9월 중순까지 새벽** | 8~9월 폭염 |
| 토요일 | 휴식 | 보조 조깅 30~40분 | 롱런 편중 완화 |
| 페이스 | 없음 | 타입별 가이드 내장 | 하프 2:14:33(6'22") 기준 산출 |
| 보급 | 없음 | 18km+(5주차~) 젤 연습, 10주차 대회 리허설 | 레이스 보급은 연습한 것만 몸이 받는다 |
| 통증 대응 | 기록만 | **신호등 규칙 + 자동 경고** | 0~3 진행 / 4~5 주의 / 6+ 중단 |

### 2차 검토 (2026-08-24, 3주차 시점)

| 항목 | 이전 | 수정 | 이유 |
|---|---|---|---|
| **감량주** | 없음 (10주 연속 증가) | **6·9주차 삽입** (-11%) | 최대 결함. 훈련 효과는 부하가 아니라 회복에서 나온다 |
| 롱런 | 전 구간 단일 LSD 페이스 | **마지막 20~25% 대회 페이스** (6주차~) | 30km 미경험을 보완하는 핵심 장치. 지친 다리로 MP 유지 |
| 목요일 | 리듬 유지주 고정 | **빌드업 / 지속주 / 크루즈 인터벌 로테이션** | 단조로움 해소. 9월 중순부터 (폭염 회피) |
| 역치 훈련 | 없음 | **8주차 1회, 4×6분으로 분할** | 연속 템포는 경골 부하가 커서 배제 |
| 빈도 | 주 3회 (토요일 선택) | **6주차부터 주 4회 고정** | 뼈·힘줄은 총량보다 부하 **빈도**에 반응 |
| 화요일 | 8km | **10km** (9주차 감량주에 전환) | 롱런 비중 58% → 51%. 총부하 증가 없이 전환 |
| 대회주 | 화 3km 후 완전 휴식 4일 | **화 4 / 목 3 / 토 2km 셰이크아웃** | 4일 쉬면 다리가 죽는다 |
| 3주차 | 화·목·일 | **목·일** (화요일 삭제) | 8/23 롱런이 8/24로 이월 |

**결과:** 피크 주간 55km / 롱런 비중 51% / 최장 롱런 28km(3:30 = 대회 시간의 72%)

### 4차 검토 (2026-09-07, 4주차 롱런 이월 시점) — 롱런 월요일 고정

| 항목 | 이전 | 수정 | 이유 |
|---|---|---|---|
| 롱런 요일 | 일요일 | **월요일** (9/7~) | 주말 롱런 불가. 9/6 롱런을 9/7로 이월하며 전환 |
| 요일 배치 | 화 회복 · 목 퀄리티 · 토 보조 · 일 롱런 | **수 회복 · 금 퀄리티 · 일 보조 · 월 롱런** | 전부 +1일. 보조→롱런 연속 배치와 하루 휴식 간격 구조는 그대로 |
| 주 구분 | 월~일 | **화~월** (`PLAN_START` 8/11) | 월요일 롱런이 그 주의 마지막 세션으로 집계되도록 |
| 대회주 | 화 4 / 목 3 / 토 2 | **수 4 / 금 3 / 토 2** | 마지막 롱런 11/9(월), 대회 6일 전 |
| 리허설 | 10/18(일) | **10/19(월)** | 대회 시작 시각 세팅이 관건 — 오전 확보 못 하면 10/18(일)로 |

주간 거리·롱런 진행(15→18→14→20→24→20→28→20→16→12)은 변화 없음.

```
주간 거리   8 → 22 → 20 → 29 → 36 → 32 → 42 → 46 → 41 → 55 → 41 → 30 → 23 → 대회
롱런        8   10   13   15   18   14   20   24   20   28   20   16   12   42.195
                                   감량              감량   피크 ├──── 테이퍼 ────┤
```

> 30km 이상을 한 번도 뛰지 않는 것은 의도된 설계다. 5시간대 완주자에게 30km는 3:45~4:00이고,
> 그 시점에서 추가 유산소 적응은 거의 없는 반면 회복 비용이 다음 주를 통째로 먹는다.
> (Hansons는 최장 롱런을 16마일=25.7km로 고정, Daniels는 2:30에서 컷)
> 대신 **토요일 → 일요일 연속 배치**와 **롱런 후반 대회 페이스 구간**으로 같은 상태를 재현한다.

목표: **4:48~4:55 완주** (6'50"~7'00"/km, 런워크 병행).
컷오프 **5시간 확정** — 한계 페이스 7'07"/km, 여유 5~12분. 구간별 통과 목표표는 앱 가이드 탭에.

## 구조

```
index.html            앱 셸 (탭 4개 + 기록 다이얼로그)
css/style.css         라이트/다크 테마
js/data.js            14주 플랜(주 구분 화~월, 롱런 월요일)·8종 페이스 가이드·과거 기록 시드
js/store.js           localStorage 저장소 + 파생 통계 + 경고 규칙
js/charts.js          인라인 SVG 차트 (라이브러리 없음)
js/app.js             화면 렌더링
sw.js                 오프라인 캐시 (수정 배포 시 VERSION 올릴 것)
manifest.webmanifest  PWA 매니페스트
```

## 로컬 실행

```bash
python3 -m http.server 8137
# → http://localhost:8137
```

수정 후 배포하면 `sw.js`의 `VERSION` 문자열을 올려야 이전 캐시가 갱신된다.
